# rate-limiter

Модуль на Python решает, можно ли пользователю отправить сообщение прямо сейчас. Все данные лежат в памяти процесса: ни базы, ни сети.

Лимиты по умолчанию:

- не больше 5 сообщений от пользователя в одном чате за любые 10 секунд;
- не больше 20 сообщений во все чаты за любую минуту;
- у аккаунта младше 24 часов лимиты строже: 2 за 10 секунд в чате и 10 за минуту всего.

Если отправить нельзя, модуль говорит, через сколько секунд станет можно. Отказанное сообщение в лимит не засчитывается.

## Пример

```python
from datetime import UTC, datetime

from rate_limiter import RateLimiter

limiter = RateLimiter()

decision = limiter.try_acquire(
    "alice",
    "chat-1",
    account_created_at=datetime(2026, 1, 1, tzinfo=UTC),
    now=datetime.now(UTC),
)
if not decision.allowed:
    print(f"Повторите через {decision.retry_after} с")
```

Вызов `try_acquire` сразу решает и засчитывает пропущенное сообщение. Настройки передаются в конструктор: `RateLimiter(regular, new_account, new_account_age)`. Лимиты каждого уровня описывает `Limits(per_chat, chat_window, total, total_window)`.

## Что значит retry_after

Это время до первого момента, когда отправка пройдёт, если пользователь больше ничего не отправит. Это `float`: секунды с дробью, без округления. Если сработали оба лимита, берётся большее время. Подсказка учитывает переход аккаунта через 24 часа: если аккаунт станет обычным не позже, чем освободится строгое окно, ожидание равно большему из двух: времени до перехода и ожидания по обычным лимитам. При пропуске `retry_after` равен 0.0, причина отказа не возвращается.

Подсказка не знает про будущее: сообщение в другой чат может сдвинуть общий лимит.

## Принятые решения

- Для каждого пользователя один журнал записей `(время, чат)`. Счёт по чату берётся из него же.
- Граница окна не входит: запись из момента `t` считается, пока `now - t` меньше окна. Шестое сообщение ровно через 10 секунд после первого проходит.
- Аккаунт младше 24 часов получает строгие лимиты, с 24 часов ровно обычные. Дата создания в будущем значит новый аккаунт. Записи до перехода остаются в журнале и дальше считаются по обычным лимитам.
- `now` и `account_created_at` это `datetime` с часовым поясом. Окна и возраст аккаунта это `timedelta`. Значения с поясом модуль приводит к UTC, поэтому перевод часов в зоне вроде `Europe/Berlin` окна не искажает.
- Если `now` раньше последнего принятого сообщения этого пользователя, будет `ValueError`. Равное время допустимо.
- Неверные настройки (лимит меньше 1, окно не положительное, отрицательный возраст аккаунта) дают `ValueError` при создании.
- Журнал хранит записи за самое длинное из окон. Пользователи без свежих записей забываются на каждом вызове.
- Тексты исключений на английском.

## Ограничения

- Модуль не потокобезопасен.
- Системные часы модуль не читает. `now` вызывающий берёт с часов сервера прямо в момент вызова: на этом держатся самоочистка и проверка порядка времени. Если между `datetime.now()` и вызовом стоит `await`, два сообщения одного пользователя могут прийти в обратном порядке и получить `ValueError`.
- Если часы сервера откатятся (например, после синхронизации по NTP), у пользователей с журналом будет `ValueError`. У тех, чей журнал уже стёрла очистка, лимит мягче на величину отката. Скачок часов вперёд (синхронизация по NTP, выход виртуальной машины из сна) стирает окна: лимиты начинаются с нуля.
- Значения без часового пояса модуль к UTC не приводит: перевод часов для них не учитывается, два таких значения считаются в одном поясе. Смешивать их со значениями с поясом нельзя: после одного вызова без пояса остальные получают `TypeError` от Python, пока процесс не перезапустят.
- Счётчики живут в одном процессе. Несколько процессов или перезапуск обнуляют их независимо друг от друга.
